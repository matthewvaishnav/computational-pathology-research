\section{Scientific audit and provenance}
\input{figures/figure7_evidence_status_matrix}

A central methodological contribution of the program is a fail-closed
scientific-audit and provenance system that separates code correction from
empirical validation and binds every active claim to an artifact that can be
cryptographically re-verified. This is a cross-cutting research-engineering
contribution, not administrative filler: it is what makes the negative and
pending statuses reported in this manuscript trustworthy.

\subsection{Immutable evidence releases}

Three separately versioned, immutable evidence packages live under
\texttt{evidence/paired\_acquisition/}:

\begin{itemize}
\item \texttt{corrected-20260726} --- the corrected forward-valid
  paired-acquisition release (canine fixed-estimand + SCORPION fold-aware
  evidence), validated by \texttt{validate\_corrected\_paired\_acquisition\_evidence.py}.
\item \texttt{dimensionality-xcov-factorial-20260726} --- the 450-cell
  dimensionality $\times$ cross-covariance factorial, validated by
  \texttt{validate\_paired\_acquisition\_factorial\_evidence.py}.
\item \texttt{scorpion-capacity-matched-20260726} --- the 175-fit capacity-matched
  campaign, validated by \texttt{validate\_scorpion\_capacity\_matched\_evidence.py}.
\end{itemize}

Each release carries a manifest that binds source-code commits (with
tree-equivalence checks), promoted artifacts (SHA-256 and byte size), row counts,
and a claim-boundary snapshot. Validators recompute declared metrics and fail
closed on any mismatch. The corrected release also implements a living
claim-boundary contract: the immutable snapshot's canonical-text hash equals the
release-time publication hash (which can never change), while the current
authoritative claim-boundary file is a living document whose hash is reported
informationally.

\subsection{Historical withdrawal and remediation}

The authoritative claim boundary records which claims were withdrawn and why.
The 2026-07-25 remediation ledger (\texttt{docs/research/scientific-audit-remediation-20260725.md})
documents corrected defects --- for example, TransnnMIL's query-invariant
attention and unregistered topology projection, canine test-set leakage and
scale-incomparable probes, SCORPION slide-level sign-flip withdrawal, and PCam
overclaims --- and distinguishes contaminated-protocol claims from valid
corrected evidence. Withdrawn claims may be discussed as motivation for
remediation but never appear in active result tables.

\subsection{Deterministic replay and exact artifact recovery}

The real paired-scanner run originally persisted metrics but no per-cell
representations, leaving the fixed-estimand adjudication at
\texttt{fixed\_estimand\_adjudication\_not\_ready}. An exact deterministic replay
(\texttt{run\_real\_bottleneck\_representation\_recovery.py}) re-executed the
50-cell canine B32/B64 grid on CUDA using the exact frozen training
implementation (source-equivalence verified against the frozen commit), compared
every cell against its frozen per-run record under a pre-fixed $10^{-6}$
tolerance, and archived \texttt{projected\_features.npz} and
\texttt{checkpoint.pt} for all 50 accepted cells. This is provenance
remediation, not a new experiment.

\subsection{Fail-closed statuses}

Every runner uses a strict status vocabulary. Recovery uses
\texttt{complete\_exact\_real\_bottleneck\_representation\_recovery} versus
\texttt{real\_bottleneck\_representation\_recovery\_failed}. The fixed-estimand
adjudication uses a scientific vocabulary
(\texttt{complete\_no\_neural\_feature\_space\_increment\_supported}, etc.) and
reserves \texttt{fixed\_estimand\_adjudication\_failed} for integrity failures.
Poor scientific results receive scientific statuses; execution failures receive
failure statuses. Claim verdicts are \texttt{supported},
\texttt{unsupported}, or \texttt{prohibited by evidence scope}.

\subsection{Why this materially affects scientific reliability}

The audit system makes the distinction between implemented architecture,
corrected empirical evidence, negative results, and pending controlled
validation enforceable rather than stylistic. A reader can verify that an active
numerical claim binds to an immutable artifact with a recorded hash, that a
withdrawn result is not reused, and that a pending claim is labeled pending. The
negative neural-increment result and the pending TransnnMIL superiority
evaluation reported in this manuscript are themselves products of this system:
they are the outcome of fail-closed, reproducible evaluation, not of selective
reporting.
